# UI audit, 2026-10-22 — every persona's journeys, by clicking only

How it was run: each journey in `docs/USER_PERSONAS.md` was walked by clicking
only, from the persona's starting page. Signed in as the demo account (the
Talbrook group: a fictional copy of the owner's four entities with the same
shape, built for this). P3 used a throwaway new account, deleted afterwards.
Figures quoted here are the demo's.

Each problem is logged as **missing** (the capability does not exist),
**misdirect** (it exists but is hard to find or misleads) or **bug**. Each one
fixed is pinned by a click-through test in `packages/web/e2e/persona-journeys.spec.ts`,
named for its journey.

Status: **fixed** = fixed in this pass. **open** = still to do. **decide** =
needs a product decision first.

## Decisions (Mansoor, 2026-10-22)

1. **Filed and accepted.** A filed PDF on file counts as filed everywhere. Each
   filed year carries an *accepted* flag, false until an IRS transcript
   confirms the return (a TC150 for that return in its own period). It is
   computed from the catalogued transcripts on read (`GET /api/review/filing`,
   `api/src/review/filing.ts`), so a new transcript updates it.
2. **Open items.** No "no filed return" item for a year not yet due (the
   extended date when extended) or before the first record on file; that
   year's fact questions are not asked either.
3. **Amendments.** An amendment starts from the best base, normally the filed
   return (imported, else the catalogued PDF), mapped back to engine inputs
   (`api/src/services/amendment_base.ts`, `POST /api/returns/amendments`).
   Books and documents are not merged into it; whether it agrees with the
   books is shown beside it. A clean-up must agree with the books; a scenario
   (what-if) need not, and defaults to the same best base.
